**DRF CRUD using APIView**

best for creating complex API view

- Difference between Function-Based View (`@api_view`) and APIView
Function based view best for small applications but not for large applications 
Function based viewe calls itself but class based dosent calls itself
APIView gets build in methods like get(),post(),put(),delete() and you can also use partial update
You can inherit APIView or GenericAPIView and reuse logic

- Create simple CRUD (`GET`, `POST`, `PUT`, `DELETE`) API
- Test in Browser & Postman

**Comparison**

| Feature | Function-Based View (`@api_view`) | Class-Based View (`APIView`) |
|---|---|---|
| Style | Functions likhte ho | Classes likhte ho |
| Reusability | Code repeat hota hai | DRY (Don't Repeat Yourself) |
| Flexibility | Chhoti API ke liye perfect | Large project ke liye better |
| Extensibility | Custom logic manually likhna padta hai | Built-in methods jaise `get()`, `post()`, `put()`, `delete()` available |
| Inheritance | Not possible | You can inherit `APIView` or `GenericAPIView` and reuse logic |
| Readability | Simple but messy when CRUD grows | Clean and structured code |
